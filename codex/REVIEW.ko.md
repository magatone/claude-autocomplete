# Codex 변경 검토, push 전

검토 날짜: 2026-10-12. 대상은 저장소의 미커밋 변경, 실험판 Rust 패치, 실행·빌드·설치 코드와 연결된 테스트입니다. 개인이 로컬 터미널에서 한 CLI를 실행하는 사용량을 기준으로 검토했습니다.

## 하는 일

Codex 0.161.0의 기본 입력창에 로컬 영어 단어 추천을 추가합니다. 실행 명령만 별도로 등록하며 기존 Codex 데이터 홈·로그인·설정을 사용합니다. Claude 플러그인 런타임은 변경하지 않습니다.

## 발견한 사항과 처리

### 1. 필수 수정: 저장소만으로 재현할 소스가 누락됨

이전 `codex/`에는 명령 등록기만 있었습니다. 개발 PC 밖에서는 `run.ps1`·수정 실행 파일·소스 패치가 없으므로 README대로 설치할 수 없었습니다.

검증한 Rust 소스 패치와 기존 Windows 빌드·실행·집중 검증 스크립트를 포함했습니다. Mac에서는 같은 패치를 고정 커밋에 적용해 네이티브 바이너리를 빌드하는 절차를 제공합니다. 컴파일된 실행 파일은 포함하지 않습니다. Mac 실기기 검증 전까지 지원 완료로 표기하지 않습니다.

### 2. 정리: 소스 패치에 실험 문서와 실험실 스크립트가 섞임

기존 패치는 실행에 불필요한 계획서·설계서와 Windows 실험실 파일까지 공식 Codex 소스에 추가했습니다. 배포 패치를 `codex-rs/`로 한정하여 **8개 파일, 30,711바이트**를 제외했습니다. 실행·빌드 스크립트는 프로젝트의 `codex/`에서 관리합니다. 검증된 Rust 동작은 바꾸지 않았습니다.

번들 사전은 실행 시 원본 저장소에 의존하지 않기 위해 필요합니다. 16개 자동완성 테스트, 기존 키 처리 통합, UTF-8 경계 검사, 입력 차단·특수 메뉴 우선순위, Windows 인자 인용·환경 전달은 유지했습니다. 워크스페이스 lockfile 버전 정합성 변경도 반복 가능한 `--locked` 빌드를 위해 유지했습니다. 이번 검토 범위에서 추가로 삭제할 미사용 실행 코드는 찾지 못했습니다.

### 3. 문서 수정: 모드·공유·플랫폼 범위를 명확히 함

기존 서버 모드와 내장 모드는 입력창 종류가 아니라 백엔드 실행 방식의 차이입니다. 두 방식은 같은 입력창·데이터 홈을 사용합니다. Windows는 기존 관리 서버를 재사용할 수 있고, Mac 명령은 Codex 기본 실행 모드를 유지하도록 수정했습니다. `--no-daemon`을 자동 추가하거나 내장 모드로 자동 전환하지 않습니다. 공식 Codex가 정상 시작하는 Mac에서 기존 서버 재사용을 테스트해야 합니다.

같은 로컬 홈을 공유한다는 뜻이지 Windows와 Mac 사이에 기록·인증을 동기화하는 뜻은 아닙니다. 자동완성에는 API가 없지만 일반 Codex 대화는 설정된 모델·제공자를 사용합니다. 오타 교정·저장 단축어는 Codex 실험판에 없습니다.

## 이번에 확인한 것

- 배포 패치를 고정된 원본 파일에 실제 적용하고 역적용 검사 통과.
- 적용된 **21개 파일**이 검증한 실험 소스와 일치, Windows 줄바꿈만 정규화하여 비교.
- **11개 사전 파일** 내용 일치, 외부 의존성 lockfile 항목 불변.
- Windows 실행기 자가 검사 통과: 공유 홈, 관리 서버 재사용·내장 fallback, 인자·작업 폴더·부모 환경·종료 코드 전달.
- Windows 빌드 적용 자가 검사 통과: 최초·반복 적용, 인덱스 보존, staged·untracked·무관한 변경 보호.
- 한국어·영어 설치 코드 블록 일치. 문서의 Mac 등록 명령을 Windows Git Bash와 임시 실행 파일로 검사하여 인자·공유 홈·자식 환경 변수·종료 코드 전달 확인. 이는 Mac 실행 검증이 아닙니다.
- README UTF-8 및 로컬 링크 확인, `git diff --check` 통과.
